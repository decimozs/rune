# Troubleshooting

## Common Errors and Solutions

### Container won't start — "unable to open database file"

**Cause:** The Docker volume for data (`ocr_data`) was freshly created and has root permissions. The application runs as a non-root user for security.

**Fix:** This is handled automatically by the `docker-entrypoint.sh` script. If you see this error, the volume was created before the fix was in place. Remove and recreate:

```bash
docker compose down
docker volume rm exist-ocr_ocr_data exist-ocr_ocr_assets
docker compose up -d
```

### Container won't start — "Permission denied: '/app/outputs/pages'"

**Same cause as above.** The output directory volume has root permissions. Run the volume removal command above.

### Page image URL returns 404

**Cause 1:** The URL was generated by an older version of the code. If the `page_image_url` starts with `/assets/...` (no hostname), the client is looking for the image on the FastAPI server (port 8000), but images are now served by nginx (port 8080).

**Fix:** Re-process the file after updating to the latest version, or manually prepend `http://localhost:8080` to the URL path.

**Cause 2:** The image has expired. Output files are automatically deleted after 1 hour (configurable via `OCR_OUTPUT_TTL`). Re-process the file.

### "Missing API key" error

**Cause:** Authentication is enabled and you did not send the `X-API-Key` header.

**Fix:** Check your `.env` file for the configured key, or use the key management scripts:

```bash
# List available keys
uv run python scripts/list_api_keys.py --db-path app/data/ocr.db
```

### "Invalid API key" error

**Cause:** The key you sent does not match any active key in the system.

**Fix:** Check the key was typed correctly. Keys are stored as secure hashes — there is no way to recover the original key. Generate a new one if needed.

### "Unsupported file type" for a supported format

**Cause:** The MIME type detected by `python-magic` does not match what you expected. Some files saved with the wrong extension (e.g., a `.pdf` that is actually HTML) will be rejected.

**Fix:** Verify the file's actual content matches its extension. Use the `file` command:

```bash
file document.pdf
```

### Gotenberg connection refused

**Cause:** Gotenberg is not running, or the URL is misconfigured.

**Fix:**

```bash
# Check if Gotenberg is running
docker ps | grep gotenberg

# Check the configured URL
docker compose exec ocr env | grep OCR_GOTENBERG_URL

# Start Gotenberg if missing
docker compose up -d gotenberg

# Wait for it to be healthy
docker compose ps gotenberg
```

### OCR is very slow on first run

**Cause:** PaddleOCR and PPStructureV3 download model files from the PaddlePaddle CDN (Baidu cloud) on first startup. These models are several hundred megabytes combined. Subsequent starts use cached models in the `paddle_models` volume.

**Fix:** This is normal. Allow 30-60 seconds for the first startup. If models need to re-download, check the `paddle_models` volume exists:

```bash
docker volume inspect exist-ocr_paddle_models
```

### "Unable to open database file" even after removing volumes

**Cause:** The `ocr_data` volume was removed but the new volume still gets root permissions.

**Fix:** Ensure you are using the latest Docker image which includes the `docker-entrypoint.sh` permission fix:

```bash
docker compose build --no-cache ocr
docker compose up -d
```

## Checking Service Health

```bash
# Check all services
docker compose ps

# See recent logs
docker compose logs --tail=50

# Test the OCR API
curl http://localhost:8000/health

# Test nginx
curl http://localhost:8080/assets/

# Test Gotenberg
curl http://localhost:3000/health
```
